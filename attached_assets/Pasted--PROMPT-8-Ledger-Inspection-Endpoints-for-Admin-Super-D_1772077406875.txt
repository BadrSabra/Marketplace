

🔹 PROMPT 8 — Ledger Inspection Endpoints for Admin (Super-Detailed)

You are tasked with building **Admin Ledger Inspection Endpoints** for the Mit Gaber Hyperlocal Marketplace. The goal is to provide **comprehensive, secure, and paginated access** to all ledger transactions, supporting **filtering, RBAC, and detailed metadata**, ready for integration with Admin UI.

---

### 1️⃣ Endpoints Specification

| Method | Endpoint                        | Description |
|--------|--------------------------------|-------------|
| GET    | /api/admin/ledger              | List ledger transactions with filters, pagination, and sorting |
| GET    | /api/admin/ledger/:id          | Get detailed information of a single ledger transaction |

---

### 2️⃣ Access Control

- **RBAC**: Only `ADMIN` role can access these endpoints
- JWT-based authentication (`authenticate` middleware)  
- `authorizeRole(['ADMIN'])` middleware required  

---

### 3️⃣ Query Parameters (Filtering)

- **user_id** (optional): filter by user  
- **type** (optional): 'DEPOSIT', 'WITHDRAWAL', 'COMMISSION', 'REFUND'  
- **status** (optional): 'PENDING', 'COMPLETED', 'FAILED'  
- **date_from** / **date_to** (optional): ISO date range  
- **limit** (optional, default 50, max 200)  
- **offset** (optional, default 0)  
- **sort_by** (optional, default `createdAt`)  
- **sort_order** (optional, 'asc' | 'desc', default 'desc')  

---

### 4️⃣ Response Structure

```ts
interface LedgerTransactionResponse {
  id: string;
  user_id: string;
  user_role: 'CUSTOMER' | 'STORE_OWNER' | 'DRIVER';
  type: 'DEPOSIT' | 'WITHDRAWAL' | 'COMMISSION' | 'REFUND';
  amount: string;               // Decimal string
  status: 'PENDING' | 'COMPLETED' | 'FAILED';
  related_order_id?: string;
  metadata: Record<string, any>; // JSON for additional context
  createdAt: string;
  updatedAt: string;
}

Paginated Response:


interface PaginatedLedgerResponse {
  total: number;
  limit: number;
  offset: number;
  transactions: LedgerTransactionResponse[];
}


---

5️⃣ Implementation Requirements

1. Backend Layer:

Service: LedgerService.getTransactions(filters, pagination)

Use Drizzle / ORM query builder to apply filtering + sorting + pagination

Ensure queries are safe against SQL injection



2. Validation:

Zod or equivalent for query params

Enforce limit <= 200

Validate status and type enums

Validate date formats



3. RBAC Enforcement:

Only ADMIN role allowed

Return 403 Forbidden for other roles



4. Error Handling:

400: Invalid filter or query param

403: Unauthorized access

500: Internal error with logging





---

6️⃣ Edge Cases

No transactions found → return empty array, total=0

Large datasets → ensure proper pagination and performance

Invalid user_id → ignore filter (do not crash)

Filtering by multiple parameters simultaneously → combine using AND

Include metadata even if empty



---

7️⃣ Unit & Integration Tests

Unit tests:

Valid filters → correct subset returned

Invalid filters → 400 error

Unauthorized user → 403 error


Integration tests:

Pagination works with limit and offset

Sorting by createdAt ascending/descending

Filtering by user_id, type, status, date range

Ensure ADMIN access only
