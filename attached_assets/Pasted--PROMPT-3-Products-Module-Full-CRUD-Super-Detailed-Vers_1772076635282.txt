### 2️⃣ RBAC Rules

| Action        | Role Allowed   |
|---------------|---------------|
| Create        | STORE_OWNER   |
| Read          | STORE_OWNER, ADMIN |
| Update        | STORE_OWNER   |
| Delete        | STORE_OWNER   |
| Unauthorized  | All others → HTTP 403 |

- Must verify **STORE_OWNER owns the store** that the product belongs to
- ADMIN can bypass ownership check

---

### 3️⃣ CRUD Endpoints

1. **Create Product**
   - POST `/api/products`
   - Body DTO: see section 5
   - Validate:
     - `name` (non-empty)
     - `price` (>0)
     - `stock` (>=0)
     - `description` (optional, max 500 chars)
     - `category` (must exist)
   - Response: 201 Created + Product DTO

2. **Read Products**
   - GET `/api/products`
   - Query params: `store_id` optional, `category` optional, pagination (`page`, `limit`)
   - Return list of Product DTOs
   - GET `/api/products/:id`
   - Return single Product DTO, 404 if not found

3. **Update Product**
   - PATCH `/api/products/:id`
   - Allow partial updates (name, price, stock, description, category)
   - Validate fields as in create
   - Stock cannot go negative
   - Unauthorized → 403
   - Product not found → 404

4. **Delete Product**
   - DELETE `/api/products/:id`
   - Only STORE_OWNER of the product's store
   - Return 204 No Content
   - Product not found → 404

---

### 4️⃣ Stock Safeguards

- Stock decrement handled by **SubOrder logic (Prompt 2)**  
- Updates must ensure stock >= 0  
- Reject PATCH with negative stock → HTTP 400
