# Engineering Constitution

## الدور

أنت الآن كبير مهندسي المشروع (Chief Software Architect).

لقد تم الانتهاء من:

* تحليل المشروع بالكامل.
* إنشاء PRD.
* إنشاء Roadmap.
* إنشاء Product Backlog.
* إنشاء خطة التنفيذ.

المطلوب الآن هو إنشاء دستور هندسي دائم للمشروع.

هذا الدستور سيكون المرجع الوحيد لأي مطور أو وكيل ذكاء اصطناعي يعمل على المشروع مستقبلاً.

لا تكتب أي كود.

قم فقط بإنشاء وثائق داخل:

docs/engineering/

---

# 01 Engineering Principles

أنشئ المبادئ الأساسية للمشروع.

مثل:

* البساطة أولاً.
* قابلية التوسع.
* سهولة الصيانة.
* الأمان افتراضياً.
* الأداء قبل إضافة التعقيد.
* عدم تكرار الكود.
* كل Feature يجب أن تكون قابلة للاختبار.
* كل تعديل يجب أن يكون موثقاً.

---

# 02 Architecture Rules

حدد قواعد المعمارية.

مثل:

* يمنع وضع Business Logic داخل UI.
* يمنع الوصول المباشر لقاعدة البيانات من الواجهة.
* جميع العمليات تمر عبر Services.
* جميع Services مستقلة.
* جميع APIs موحدة.
* يمنع إنشاء Circular Dependency.
* يمنع استدعاء الطبقات بطريقة غير صحيحة.

# 17 AI Development Rules

هذه أهم نقطة.

إذا كان التطوير يتم بواسطة وكيل ذكاء اصطناعي.

فيجب عليه قبل أي تعديل:

* قراءة PRD.
* قراءة Roadmap.
* قراءة Engineering Constitution.
* مراجعة Backlog.
* مراجعة آخر Sprint.
* تحليل التأثير.
* عدم إنشاء كود مكرر.
* البحث أولاً عن كود مشابه لإعادة استخدامه.
* تحديث الوثائق بعد التنفيذ.
* إضافة الاختبارات عند الحاجة.
* عدم حذف أي جزء إلا بعد تحليل الاعتماديات.

# 19 Refactoring Rules

لا يسمح بإعادة كتابة أي جزء.

إلا إذا:

* أصبح غير قابل للصيانة.
* يسبب مشاكل أداء.
* يسبب مشاكل أمنية.
* يمنع التوسع.
* توجد بدائل أفضل موثقة.

---

# 20 Quality Gates

قبل اعتبار أي Feature مكتملة.

تحقق من:

✔ الكود يعمل.

✔ جميع الاختبارات ناجحة.

✔ لا توجد أخطاء Build.

✔ لا توجد أخطاء Lint.

✔ التوثيق مكتمل.

✔ الـ API موثقة.

✔ قاعدة البيانات محدثة.

✔ الأداء لم يتراجع.

✔ الأمان لم يتأثر.

✔ تم تحديث Roadmap.

✔ تم تحديث Backlog.

# 25 القواعد النهائية

اعتباراً من الآن:

* لا يتم تنفيذ أي تعديل بدون الرجوع إلى هذا الدستور.
* إذا تعارض طلب جديد مع الدستور، قم بشرح التعارض واقترح بديلاً.
* إذا احتاج الدستور إلى تحديث، أنشئ اقتراح تعديل أولاً ثم انتظر الموافقة قبل اعتماده.
* الهدف هو الحفاظ على جودة المشروع واستمرارية التطوير حتى مع تغير المطورين أو وكلاء الذكاء الاصطناعي.
