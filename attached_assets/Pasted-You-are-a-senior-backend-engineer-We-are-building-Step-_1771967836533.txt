**Goal of this Step:**

### TASKS — Step-by-Step

### 1️⃣ Delivery OTP System
- Create `server/modules/delivery/deliveryOtp.model.ts`:
  - id (uuid)
  - orderId (relation to Orders table)
  - subOrderId (relation to SubOrders table)
  - otpCode (string, 6 digits)
  - status (PENDING, VERIFIED)
  - createdAt, updatedAt
- Create `deliveryOtp.service.ts` with functions:
  - generateOtp(orderId, subOrderId)
  - verifyOtp(orderId, subOrderId, otpCode)
- Create endpoints in `deliveryOtp.controller.ts`:
  - POST /delivery/otp/generate → generate OTP (Admin/Driver)
  - POST /delivery/otp/verify → verify OTP (Customer)
- OTP verification marks delivery as completed for SubOrder

---

### 2️⃣ Commission System
- Implement commission logic in `ledger.service.ts`:
  - After OTP verification:
    - Calculate 1% commission for Customer, Store, Driver
    - Update Wallet balances accordingly
    - Create Ledger Transactions for each transfer
- Ensure atomic transactions: all balances updated or none
- Prepare structure for multi-store orders:
  - Each SubOrder can have independent commission

---

### 3️⃣ Integration
- Use existing WalletService and LedgerService
- Link SubOrders and Orders to WalletTransaction for transparency
- Keep placeholders for DeliveryOffers and future multi-driver bids
- Ensure OTP verification triggers automatic commission distribution

---

### 4️⃣ Notifications
- Send email notifications using Notifications module:
  - OTP Generated → Driver notified (optional)
  - Delivery Verified → Customer, Store, Driver notified
- Use async email sending with logging

---

### 5️⃣ Validation & Error Handling
- Validate OTP code (6 digits, numeric)
- Only authorized Customer can verify OTP
- Ensure LedgerService handles decimal values correctly
- Log all errors and failed attempts
